# Lab 04: Windows Firewall & Endpoint Network Security — Firewall Configuration and Connectivity Validation

## 📌 Executive Summary

This lab simulates an endpoint firewall configuration and validation task within an enterprise Windows environment.

The objective is to demonstrate a controlled host-based firewall configuration process that incorporates firewall status verification, profile review, outbound application rule creation, connectivity testing, configuration rollback, and post-test validation.

The lab uses **Microsoft Defender Firewall** and **Mozilla Firefox** to demonstrate how an outbound program-based firewall rule can restrict an application's network connectivity on a Windows workstation.

The configuration and testing process is documented as an enterprise IT support workflow rather than as a simple firewall configuration exercise.

---

## 🎯 Objectives & Scope

This lab demonstrates the following endpoint network security practices:

* Verify the operational status of Microsoft Defender Firewall.
* Review the status of the available Windows Firewall profiles.
* Access Windows Defender Firewall with Advanced Security.
* Identify the appropriate firewall rule type and traffic direction.
* Create an outbound program-based firewall rule for Mozilla Firefox.
* Configure the rule to block network connections generated by the application.
* Validate the expected connectivity restriction through a controlled test.
* Disable or remove the test rule after validation.
* Verify that application connectivity is restored after the rule is rolled back.
* Document the configuration, testing results, and supporting evidence.

### Out of Scope

* Enterprise network firewall administration
* Active Directory or Group Policy-based firewall management

## 🔐 Security Controls Demonstrated

The lab focuses on endpoint firewall controls that help manage application network access and validate the enforcement of security configurations.

### Firewall Status Verification

The Windows Firewall status is reviewed before creating the test rule. The available firewall profiles are checked to establish the initial security configuration.

### Outbound Traffic Control

An outbound program-based rule is created for Mozilla Firefox. The rule is configured to block network connections generated by the specified application.

### Rule Configuration Review

The rule's application path, traffic direction, and configured action are reviewed to ensure that the test rule reflects the intended configuration.

### Enforcement Validation

The test application is used to verify the rule's behavior. A failed connection attempt provides behavioral evidence of the restriction, although the failure alone does not prove that the firewall is the cause; the baseline and rule state must also be considered.

### Configuration Rollback

After the blocked state has been validated, the test rule is disabled or removed. This prevents the temporary test configuration from unnecessarily restricting normal application connectivity.

### Post-Test Connectivity Validation

The application is tested again after rollback. The results are compared with the initial baseline to determine whether connectivity has been restored.

### Evidence-Based Documentation

Screenshots and validation records are collected to document the initial configuration, rule creation, observed behavior, rollback, and final state.

## 🔎 Expected Outcome

At the end of the lab, Microsoft Defender Firewall should have been reviewed and its relevant configuration documented. The outbound Firefox rule should demonstrate the expected network restriction during testing, and the subsequent rollback should allow connectivity to be tested again.

The documentation should provide evidence that:

* The initial firewall status was reviewed.
* The relevant firewall profiles were inspected.
* An outbound program-based rule was configured for Mozilla Firefox.
* The rule was set to block the application's network connections.
* The blocked behavior was tested and documented.
* The temporary rule was disabled or removed after testing.
* Connectivity was tested again after rollback.
* The final configuration and observed results were documented accurately.

The final report will distinguish between the configured rule, the observed test results, and the conclusions supported by the collected evidence.
